# Supported Protocols
{: .section-header.mt-1 }

Arkime recognizes **203 protocols**. This page lists every one of them, along with the
exact value to put in a `protocols ==` search.

### Classifiers vs Parsers
{: .subsection-header }

A **classifier** identifies a protocol by matching known byte patterns or port numbers in the network traffic.
When Arkime classifies a session, it tags the session with the protocol name so you can filter on it (e.g. `protocols == redis`), but it does not extract any protocol-specific fields.
Classifiers are lightweight and allow Arkime to recognize a wide range of protocols with minimal overhead.

A **parser** goes further than classification.
In addition to identifying the protocol, a parser deeply inspects the protocol's content and extracts structured fields into the session metadata.
For example, the DNS parser extracts query hostnames, response IPs, query types, and more.
Parsed fields are fully searchable and viewable in Arkime's UI.

The **Fields** column is approximate. It counts the field definitions in each parser's
source, which is close to, but not exactly, the number of fields you can search on:
a definition flagged to keep a count also creates a `.cnt` companion, some definitions
are regex shorthands that are never stored, some register extra aliases, and HTTP
defines one field per method inside a loop that counts here as a single definition.
Read it as a sense of how much a parser pulls out, not an exact total.

### Protocol Table
{: .subsection-header }

A single parser often tags more than one protocol, so some rows list several values.
Searching for any one of them works: `protocols == dhcpv6`, `protocols == mdns`, `protocols == cip`.

Rows marked <sup class="proto-fn">*</sup> in the table above have a note here.
{: #protocol-notes }

* **TLS/SSL** includes the certificate fields, which live in a shared helper used by both TLS and DTLS.
* **POP3** and **TDS** define no fields of their own; they fill in Arkime's shared `user` field.
* **WebSocket** runs as a sub-parser of HTTP, so it only sees traffic HTTP has already upgraded.
* **AD CS over HTTP**, **WinRM** and **RPC over HTTP** are matched on the HTTP request path, so they only appear on sessions HTTP itself parsed.
* **`sccp` means two unrelated things.** On TCP port 2000 it is Cisco Skinny, a VoIP
  call-control protocol, matched by a classifier. Inside SS7 over M3UA it is the
  Signalling Connection Control Part, parsed together with TCAP. Both tag the session
  `sccp`, so add a port or an `isup`/`m3ua` term when you need to tell them apart.

### DCE/RPC Interfaces
{: .subsection-header }

When the DCE/RPC parser sees a bind to a known interface UUID, it tags the session with
that interface's name as well as `dcerpc`. These are worth knowing because so many
Windows attack paths are a single named interface: `protocols == drsuapi` finds DCSync,
`protocols == rprn` finds PrinterBug and PrintNightmare, `protocols == efsrpc` finds
PetitPotam, and `protocols == netlogon` finds ZeroLogon.

<script>
  (function () {
    var $table = $('#protocolTable');
    if (!$table.length) { return; }

    var $rows = $table.find('tbody tr');
    var $count = $('#protoCount');
    var $none = $('#protoNoResults');
    var $search = $('#protoSearch');
    var type = 'all';
    var total = $rows.length;

    // Cache the searchable text and type of every row once.
    $rows.each(function () {
      var $r = $(this);
      $r.data('protoText', $r.text().toLowerCase());
      $r.data('protoType', $r.find('.proto-parser').length ? 'parser' : 'classifier');
    });

    function apply () {
      var q = ($search.val() || '').trim().toLowerCase();
      var shown = 0;

      $rows.each(function () {
        var $r = $(this);
        var ok = (type === 'all' || $r.data('protoType') === type) &&
                 (q === '' || $r.data('protoText').indexOf(q) !== -1);
        $r.toggle(ok);
        if (ok) { shown++; }
      });

      $none.toggle(shown === 0);
      if (q === '' && type === 'all') {
        $count.text('Showing all ' + total + ' protocols.');
      } else {
        $count.text('Showing ' + shown + ' of ' + total + ' protocols.');
      }
    }

    $search.on('input', apply);

    $('[data-proto-type]').on('click', function () {
      $('[data-proto-type]').removeClass('active');
      $(this).addClass('active');
      type = $(this).data('protoType');
      apply();
    });

    apply();
  })();
</script>
